Run a software project as a graph of gated work. Prove the rules in code.

A queue of rows becomes specs, decisions and vertical-slice tasks. Isolated implementers build the tasks in parallel in worktrees, a fresh context verifies each one, an adversary hunts the loopholes, the loop merges, and a human releases. The discipline lives in scripts, hooks and a guard, not in prompts.

Start here

Pick your situation. One command each.

The same five rows as the README's quick start, one at a time. Every command below is a Claude Code slash command inside your project.

A new project

/reef-init

One batched question set. The branches and the architecture grill: host, shape, scale, store, auth boundary, one-year non-goals.

What happens. Reef renders one tree from templates adapted to your stack: .reef/config.json (every number, once), AGENTS.md, the constitution, the queue with batch 1 row 1 = the walking skeleton, reef/architecture/architecture.md (intent, C4 L1/L2) with draft ADRs for shape, host, store and auth, the journal, glossary, day-zero, a release-only CI, Dependabot, the git hooks, and every scripts/reef-*.

Idempotent: a second run with nothing changed writes nothing.

An existing project

/reef-init
/reef-assess

Nothing you wrote is overwritten. A differing rendering lands in .reef/proposed/<path> with a diff; apply the ones you choose:

python3 scripts/reef-init.py --accept <path>

What happens. /reef-assess reads how the project works, was written and was pushed, with every claim Observed with a proving path or Inferred. It scores how well a harness can hold the project, then recalibrates its documents into the tree under one batched approval.

Archive, never delete. Undo with one git revert.

A feature to build

/reef-plan <row>→/reef-plan-review→/reef-task <slug>→/reef-review <slug>

Four commands, one human question in the middle of the first: Approve plan <slug> at <digest16>?

What happens. The grill, the spec and the tasks. The deterministic check and the semantic review. The task graph: every ready task at once, each in its own worktree, verified by a fresh judge. Then the PR, the acceptance against SPEC.md, the diff review, the merge and the close.

Each stage is explained in How it works.

A queue of rows

/reef-loop

The outer graph: every ready row through the four feature commands, in parallel where rows do not collide.

What happens. The loop stops only for the owner's decisions, a missing credential, a wrong spec, or a cap. Its questions are batched. State lives on disk, so a new session reads the handoff head and one tick, about 300 tokens, and continues every row from its furthest completed step.

Without a gh-authenticated forge, Reef stops with USER ACTION REQUIRED and says exactly what it would have run.

A fresh clone

make setup

Hooks are local git config and do not survive a clone.

Upgrading from 0.5. Re-run /reef-init. scripts/reef-migrate runs first and adds only keys, keeps gates.test as the alias it is, and writes .reef/version. Every check new in 0.6 warns on content planned under 0.5 and fails only on content planned under 0.6.

The flat tasks/ and docs/ layout keeps working; python3 scripts/reef-migrate --layout moves it in one reviewed commit when you want the tree.

How it works

From a queue row to a merge, seven stages. Click one.

Two human gates in the whole run: the plan approval and the release merge. Everything between them is decided by code on state the agent cannot author. A dark dot marks a stage where a human decides.

01 · The queue row human writes

reef/queue.md is the outer graph: rows with an id, Depends, a source (planned before found) and a batch. The queue has one home, on the base branch in the main checkout; a feature branch whose queue differs from its fork point fails the plan check.

Writes

Nothing yet. A row is a sentence and a batch number.

Gate

The row is in the current batch and every row it depends on is closed.

Enforced by

  • reef-queue.py status | ready | check code
  • reef-loop.py tick reads the ready rows

Human

Writes the rows. The grill in /reef-init seeds row 1 with the walking skeleton.

02 · /reef-plan gate 1 of 2

Grills the owner, then writes the feature folder reef/features/<slug>/: a SPEC.md with layered FR-n/SC-n keys, one ADR with a diagram, and vertical-slice tasks whose criteria cite those keys and whose proof is a test name or a command. Then it asks the one human question.

Writes

  • SPEC.md, adr/draft-*.md, tasks/NNNnn-*.md
  • the grill's rows on the base branch, before feat/<slug> exists

Gate

Approve plan <slug> at <digest16>? The approval is a record bound to the plan's digest. An edit afterwards approves nothing.

Enforced by

  • PostToolUse hook scripts/reef-approval.py writes .reef/approvals/<slug>.json only on Approve at the current digest code
  • nobody writes an approval by hand tripwire

Human

Yes. Answers the grill, approves the plan at its digest.

03 · /reef-plan-review

A deterministic check first, then, for anything heavier than light, a plan-reviewer agent in a fresh context. A design or critical task also gets the loophole-hunter on the plan before any code, with one question: how can every check be green while the defect happens?

Writes

  • a stamp over the whole feature folder
  • .reef/review/plan-<slug>.json: a PASS bound to the plan's digest
  • an adversarial PASS record for design and critical tasks

Gate

14 to 19 checks (reef-plan-check.py --rules prints them with your numbers): slug, keys, criteria cite keys of their own folder, at most plan.max_tasks, criterion and sentence length.

Enforced by

  • reef-plan-check.py --verify-stamp, re-checked by the guard at every dispatch code
  • scripts/reef-record plan-review, scripts/reef-adversarial code

Human

No. A plan with every task light needs no reviewer; the deterministic check alone stamps.

04 · /reef-task, the task graph

Computes the ready set from disk and dispatches every ready task at once, each in its own worktree on its tier's model. Per task: an implementer builds it by TDD and hands back; a verifier in a fresh context writes its pass/fail rule per criterion before reading the diff; the hunter runs again on a finished guard; the task merges into the feature branch. A tree hash proves the judges touched nothing.

Writes

  • code and tests, in .reef/worktrees/<id>
  • .reef/inflight/<id> on dispatch, the judge's report verbatim, tasks/done/ on merge

Gate

The guard refuses a dispatch outside the ready set, over the retry cap (caps.attempts), on the wrong model, without the approval or the review record, or over the context ceiling.

Enforced by

  • reef-guard.py on every Task/Agent call code
  • reef-graph.py (the ready set), reef-attempt (the cap, the models), reef-snapshot.sh (the hash) code
  • judges are read-only: the write detection is a token match tripwire

Human

No. The Stop hook refuses a turn that leaves ready work idle.

05 · /reef-review

Pushes the feature branch and opens the PR. scripts/reef-converge checks that every Proof row holds on the branch. Then the acceptance against SPEC.md, the diff review, one rollup under one cap, and the CI or local gate driven green.

Writes

  • the PR
  • a GREEN record bound to the forge head (scripts/reef-record)

Gate

gh pr merge only against a GREEN record at the PR's current head. A rebase or a code push after the record invalidates it; only claims-only commits carry over.

Enforced by

  • reef-guard.py on gh pr merge and gh api …/merge code
  • reef-claims.py: hand-backs and reports within their word caps, claims that point inside the diff code
  • local CI = CI: every exit code read, a skip is exit 2 code

Human

merge.by: human (the default) merges the feature by hand; merge.by: loop lets the loop merge against the GREEN record.

06 · Merge and close gate 2 of 2

The feature merges into branches.base and the close happens in the same breath: draft ADRs are numbered in one global sequence, the row is archived with the owner's words, the journal row is written from measured state, and the handoff is rewritten whole. The release PR from the base to branches.release runs gates.release once, and the human merges it.

Writes

  • reef/architecture/adr/NNNN-*.md, reef/queue-archive.md, reef/journal.md, HANDOFF.md

Gate

gates.release: C4 drift (reef-c4.py --diff), threat-model lint, a secret scan, the stack's audit. A missing tool is a skip, and a skip is exit 2, not success.

Enforced by

  • reef-queue.py adr-number, reef-handoff code
  • reef-ci-local.sh --release code
  • the release branch protected, push protection, CODEOWNERS: scripts/reef-repo code

Human

Yes. Merges the release PR. There is no push gate by design: a worktree gate at push time only false-rejects, CI is the wall.

07 · Resume anywhere

State lives on disk. A new session's SessionStart hook runs one tick and prints the handoff head and the next command, about 300 tokens against an 8,000 cap. Every row continues from its furthest completed step. The tick never advertises a task whose plan lacks the human's approval at the current digest; it says awaiting: <feature> (approval | re-approval | plan review) instead.

Writes

  • HANDOFF.md, rendered whole from measured state, also by the guard itself at the context ceiling

Gate

caps.context_tokens and caps.dispatch_reserve: a dispatch without room is denied after a checkpoint, with “/clear now”.

Enforced by

  • hooks.json SessionStart → reef-loop.py tick --session-start code
  • hooks.json Stop → reef-loop.py tick --assert-no-idle code
  • reef-cost.py --live on the transcript tail code

Human

Runs /clear when told. scripts/reef-watch shows what happened while nobody was in the room.

a human decides here code on structured state tripwire on command text prose in a skill or agent file
Who does what

Six roles. Three of them may not write.

Every dispatch starts with a REEF-TASK: or REEF-FEATURE: line, so the guard knows the tier and refuses the wrong model. A denial names the role; these cards say what each role may do.

Orchestrator dispatches

The main session. Reads one tick, not the world; dispatches the ready set; never implements. Its context has a ceiling and a warning, and it checkpoints itself before refusing a dispatch.

skills/reef-task, reef-loop

Implementer writes

Builds one groomed task by TDD, code and tests. Never commits, never verifies its own work. Hands back at most writing.handback_words with a claims list.

agents/implementer.md · tier author model

Verifier read-only

A fresh context that writes its pass/fail rule per criterion before reading the diff, attacks the last round's fix first, and reports evidence per criterion. Only four kinds fail: regression, bypass, correctness, a failed criterion.

agents/verifier.md · snapshot hash before and after

Loophole-hunter read-only

The adversary. Runs twice on a design or critical task, on the plan and on the finished guard, and once per release against the threat model. A BLOCKER fails the pass; a NEW-ROW becomes a queue row.

agents/loophole-hunter.md · never on mech

Plan-reviewer read-only

Reviews an approved plan for drift between its artifacts: spec, ADRs, tasks, config. Citation-required. Its verdict is a record bound to the plan's digest; a contradiction between two sources of truth is a halt, never an auto-fix.

agents/plan-reviewer.md

Mechanic writes, no claims

Light work a machine can check: rebase, run the gates, re-take a measurement, archive edits. Its output is exit codes, git range-diff and digests, never prose. Runs on the cheapest model.

agents/mechanic.md · sonnet by default
The honesty ledger

What is enforced, and how.

Three classes. Code decides on structured state the agent cannot author. A tripwire matches command text, and a blocklist over a shell is never complete, so CI is the wall. Prose lives in a skill or agent file. This table is read from the README at page load, so it cannot drift from it.

Reading the ledger from the README… If this stays here, read it on GitHub: What is enforced, and how.

Every scripts/reef-* carries # CLASS: in its header, and tests/test_contracts.py ties each row to a script of that class. A change to a CLASS: code script without a tests/ change fails the PR.

Who runs what

Four tiers. A tier only gets heavier.

Each tier names a model per role and an effort, resolved at dispatch by scripts/reef-attempt and refused by the guard on mismatch. Path classes and touches: force a tier upward: pii, money or auth is critical; a migration is design and needs a Rollback:.

TierWhenJudgesAuthorEffortVerify
criticalFirst-time analysis, architecture, the constitution, the threat model, touches: money|pii|auth, the guard's own paths.If this is wrong, the project is wrong.opusopus set a heavier model per projecthighjudge; the adversary on the plan and on the guard
designTwo people would build it differently; a mechanism that failed twice; auth, crypto, secrets, migration paths.The shape is a decision.opusopushighjudge; the adversary twice
fullThe default.Ordinary feature work.opusopusmediumjudge
lightAllowlisted paths (docs/**, README.md), no risk path, under the line ceiling (80).A machine can check it whole.none the deterministic check alone stampsopus sonnet not shipped: unproven by the evallowgate + golden test, no judge

Agent files carry a default model equal to the role's default; the dispatch-time model always overrides it. An unset tier table is exactly the 0.5 roles.* behaviour.

Layout

One tree, grouped by feature.

Machine state in .reef/, three files at the root, every committed artifact under reef/, tooling where git and CI expect it. Expand a folder to see what each file is for.

  • AGENTS.mdthe rules every agent meets first, at most 80 lines
  • CLAUDE.mda pointer to AGENTS.md
  • HANDOFF.mdrewritten whole from measured state at every close; a new session reads its head

    • config.jsonevery number, once
    • versionwritten by reef-migrate
    • loop.json · inflight/ · verifying/the loop's state and the in-flight markersgitignored
    • approvals/ · review/records written by hooks and scripts only; the guard denies a hand writegitignored
    • worktrees/ · proposed/ · ci-local/task worktrees, init's proposed renderings, local CI logsgitignored
