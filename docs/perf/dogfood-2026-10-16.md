# Reef 0.7 — the dogfood run (2026-10-16)

Reef run on itself and on a fresh project, every stage in its own headless Claude Code session (`claude -p` with
`--plugin-dir`, the session persisted), measured with `scripts/reef-cost.py` over each transcript. Nothing here was
typed by a human during a run: where a skill asks the owner, the owner's answers were given in the prompt in
advance, and the plan approval was recorded by replaying the AskUserQuestion hook (`scripts/reef-approval.py`) with
the owner's authorisation, because headless sessions exclude that tool.

Cost figures are Claude Code's own `total_cost_usd` estimate at API list prices. The CLI here is signed in with a
subscription (`authMethod: oauth_token`), so nothing was invoiced; the runs consumed plan usage.

## Method
- Orchestrator model `fable` (the same as the session that built 0.6); roles on the tier tables (`critical` for Reef's
  own scripts, `full` by default on the sample project); `--permission-mode bypassPermissions`; one budget cap per stage.
- `growth` = the sum of the positive context deltas over consecutive main-session turns (so a compaction cannot hide
  growth); `first` = the first turn's context; `max` = the largest; categories as `reef-cost.py` splits them.
- The scratch projects: `reef-row` (a clone of Reef with `reef-init` applied, row 1 = `cost-rows-growth`, tier
  critical) and `ledger` (a fresh Python project: pyproject, one package, one smoke test).

## C. Defects found by dogfooding (fixed on this branch, each with a red test)
1. `reef-plan-check.py` read `adr/README.md` (which `reef-init` writes) as an ADR without a Status: every fresh
   0.6 project failed its first plan check. `tests/test_plan_check.py::test_adr_readme_is_not_an_adr`.
2. `reef-plan-check.py` died with ENOENT writing its stamp on a fresh 0.6 project (no `tasks/` yet), after printing
   "0 failed". `tests/test_feature_spec.py::test_fresh_06_project_without_tasks_dir_gets_its_stamp`.
3. `reef-adversarial` refused the hunter's live PASS report because it said `BLOCKER: none.`, and did not read a
   bold `**BLOCKER:** …` as a blocker at all. `tests/test_adversarial.py::test_blocker_none_is_no_blocker` plus a
   bold refusal case.
4. `reef-queue.py adr-number` produced `# ADR ADR 0001 — …` titles from `reef-init`'s own drafts and turned a path
   citation into the dead `adr/ADR 0001.md`; the ledger close corrected four spots by hand and reported it.
   `tests/test_tier_queue.py::test_adr_number_title_and_path_citations`.
5. The approval hook lives in the plugin, not the project: `reef-init` does not copy `reef-approval.py`, so the
   replay for the sample project had to call the plugin's copy. By design, noted here because the handoff of a
   headless run must say which script to replay.
6. **`templates/pre-commit` ran the gate inside git's hook environment** (`GIT_DIR`, `GIT_INDEX_FILE`,
   `GIT_WORK_TREE`, `GIT_PREFIX` exported), so a project whose test suite runs its own `git init` / `git commit`
   fixtures corrupts its own repository at every commit. Reef's suite does; the Reef-on-itself row hit it, the
   orchestrator restored the repo from the reflog and stopped. The gate now runs in a subshell with those unset, plus
   `GIT_CONFIG_PARAMETERS` (a committer's `git -c` reached the gate's git the same way, found while finishing the row).
   `tests/test_hooks.sh`: two checks, red before.
7. `reef-claims.py report` demanded `RULE AC<n>` lines of the loophole-hunter, whose report shape has none; every live
   hunter report was rejected and `/reef-task` had to re-dispatch "shorten, evidence only" for nothing. The hunter
   shape is now checked on its own terms. `tests/test_feature_spec.py::test_hunter_report_has_its_own_shape`.
8. Noted, not fixed (0.7 rows the orchestrator filed): `worktree.setup` is empty by default and `.reef/` is
   gitignored in Reef's own repo, so a task worktree of Reef itself has no `.reef/config.json` and the gate has to
   autodetect the test command (a project that commits its config, like `ledger`, is unaffected); and the hunter's
   seven NEW-ROWs on the rows feature (a second notification for one id, a string-shaped `tool_use.input`).

## E. What the numbers say, and the caps

| Session | growth | max context |
|---|---|---|
| `/reef-init` | 11k | 58k |
| `/reef-plan` (one row, 2 tasks) | 66k | 114k |
| `/reef-plan-review` | 25k | 70k |
| `/reef-task` (2 tasks, tier full) | 63k (39.7k inside the dispatch span) | 111k |
| `/reef-review` | 54k | 102k |
| close | 39k | 86k |
| `/reef-task` (1 task, tier critical, Reef on itself) | 111k (34.1k inside the span) | 159k |

- The 5.7 target ("one full row grows the orchestrator's context by under 60k") was written for the task graph. Measured
  inside the dispatch span, both graphs meet it (34k, 40k); measured as whole `/reef-task` sessions they do not (63k,
  111k), and a whole row across its five sessions costs 246k. The item that breaks the target, per the plan's own rule,
  is **`/reef-plan`**: 66k for a two-task row, mostly Bash output (24.7k) and the files it writes inline (8k). That is
  the next cut, and it is the owner's design decision (the grill and the drafting are where the planner reads the
  repository whole).
- Every session starts at 46–48k before the first turn: the system prompt, the plugin's skill text and the attached
  files. The SessionStart injection itself is about 300 tokens against the 8,000 cap. The 0.5 baseline's 91k first turn
  is gone; the floor is Claude Code's.
- **Caps set from these numbers** (the 5.7 row's second half): `caps.context_warn: 100000`, `caps.context_tokens: 150000`
  in `templates/config.json`. The warning fires late in a planning or critical-row session (p90 of the session maxima is
  148k), the ceiling only on a runaway; a 60%-of-window ceiling (120k) would have cut the critical row in two at its
  verifier dispatch. A project that wants the tighter 40/60 split sets it; the README says why the default is wider.
- `writing.report_words`: four real reports measured at 538–706 words for 6–7 criteria (about 95 per AC);
  recommendation 900, left for the owner to set (one line in `templates/config.json`).
