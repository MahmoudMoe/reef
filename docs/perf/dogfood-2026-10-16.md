# Reef 0.7 — the dogfood run (2026-10-16)

Reef run on itself and on a fresh project, every stage in its own headless Claude Code session (`claude -p` with
`--plugin-dir`, the session persisted), measured with `scripts/reef-cost.py` over each transcript. Nothing here was
typed by a human during a run: where a skill asks the owner, the owner's answers were given in the prompt in
advance, and the plan approval was recorded by replaying the AskUserQuestion hook (`scripts/reef-approval.py`) with
the owner's authorisation, because headless sessions exclude that tool.

Cost figures are Claude Code's own `total_cost_usd` estimate at API list prices. The CLI here is signed in with a
subscription (`authMethod: oauth_token`), so nothing was invoiced; the runs consumed plan usage.

## Method
- Orchestrator model `fable` (the same as the session that built 0.6); roles on the tier tables (`critical` for Reef's
  own scripts, `full` by default on the sample project); `--permission-mode bypassPermissions`; one budget cap per stage.
- `growth` = the sum of the positive context deltas over consecutive main-session turns (so a compaction cannot hide
  growth); `first` = the first turn's context; `max` = the largest; categories as `reef-cost.py` splits them.
- The scratch projects: `reef-row` (a clone of Reef with `reef-init` applied, row 1 = `cost-rows-growth`, tier
  critical) and `ledger` (a fresh Python project: pyproject, one package, one smoke test).

## B. Reef on itself: one critical-tier row (`reef-row`, row 1 `cost-rows-growth`)

### The plan pass (loophole-hunter, fable, `pass=plan`)
| Round | verdict | cost | what it caught |
|---|---|---|---|
| 1 | FAIL | $2.14 | the dispatch tool in real transcripts is `Agent`, not `Task` (the plan would have measured nothing); growth = last − first reads low or negative across a compaction |
| 2 | FAIL | — | a single-dispatch feature has no consecutive turns in its span (growth 0) and the turn carrying the last dispatch's result falls outside every span; plus one scoping gap (Bash `claude -p` subprocesses are not Reef dispatches) |
| 3 | FAIL | $1.94 | the Agent tool runs in the background here: the next turn's `tool_result` is a stub and the real result is a later `<task-notification>` user record, so "the turn after" measured the stub; SC-1 named a session that dispatches through Bash subprocesses, where the feature prints nothing |
| 4 | FAIL | $1.92 | a real Agent `tool_result` has list-shaped content, the test fixture builder writes strings: an implementation reading strings only passes the tests and misses every real dispatch |
| 5 | FAIL | $2.18 | no fixture made "by id" and "by position" disagree, so a positional implementation passed every listed test |
| 6 | FAIL | $1.92 | the notification shape was asserted, not captured in the payload ledger; Scope and FR-2 contradicted the Decision on the slug of the absolute path `reef-attempt` prints |
| 7 | (running) | | after capturing a real notification into `tests/fixtures/payloads/user-task-notification.json` and making the notification win over the `tool_result` |

Every blocker above was real and went into the plan before any code. Six rounds on a 60-line task file is the
measured cost of a plan that parses a format nobody had written down: the hunter probed the real transcripts on disk
each time and found the format's next corner. Cumulative plan-pass cost about $12 at list prices. The plan went through `reef-plan-check`
(14 checks) and the digest-bound approval each round.

## C. Defects found by dogfooding (fixed on this branch, each with a red test)
1. `reef-plan-check.py` read `adr/README.md` (which `reef-init` writes) as an ADR without a Status: every fresh
   0.6 project failed its first plan check. `tests/test_plan_check.py::test_adr_readme_is_not_an_adr`.
2. `reef-plan-check.py` died with ENOENT writing its stamp on a fresh 0.6 project (no `tasks/` yet), after printing
   "0 failed". `tests/test_feature_spec.py::test_fresh_06_project_without_tasks_dir_gets_its_stamp`.
