# Hook payloads — verified on Claude Code 2.1.301 (2026-10-16)

Item 0.0 of the 0.6 plan. Every payload under `tests/fixtures/payloads/` was captured verbatim from a
live headless session (`claude -p --model haiku`, scratch project with a dumping hook on every event);
only absolute paths were rewritten. One fixture is **schema-derived**, not captured, and says so in its
`_source` field. Items 1.3, 1.4, 1.5, 5.2, 5.4 and 6.2 read this file before they are built.

| Question | Answer | Evidence | Consequence |
|---|---|---|---|
| (a) Does a PreToolUse `Bash` payload fired inside a sub-agent carry `agent_type` and `agent_id`? | **Yes.** `agent_id: "a2950feec40c097e0"`, `agent_type: "general-purpose"`; the main-thread payload carries neither. | `pretooluse-bash-subagent.json` vs `pretooluse-bash-main.json`; the binary's common-input schema: "agent_id … Present only when the hook fires from within a subagent … Use this field (not agent_type) to distinguish subagent calls from main-thread calls." | 1.3 reviewer lock is class **code**: the guard reads `agent_type`; a sub-agent call with `agent_id` and no `agent_type` is locked while a `.reef/verifying/<task>` marker exists (belt). |
| (b) PostToolUse `AskUserQuestion`: where does the chosen label live? | `tool_response.answers` maps **question text → answer label** (multi-select comma-separated); `tool_response.response` holds free text typed instead of an option; `afkTimeoutMs` is set when the dialog auto-resolved idle. `tool_input.answers` exists only when a host supplied them via `updatedInput`. | Binary zod schema for the tool's result: `questions, answers: record(string,string), response?, annotations, afkTimeoutMs?`. **Not captured live**: headless `-p` sessions exclude `AskUserQuestion` from the tool set even with `--tools AskUserQuestion` (two attempts, `tests/fixtures/payloads/posttooluse-askuserquestion-schema.json` records the shape). | 1.2 `reef-approval.py` reads `tool_response.answers` first, `tool_input.answers` second; a payload with `afkTimeoutMs` (timeout answer) writes nothing; the README ledger marks the record **code (schema-verified, not live-verified)**. |
| (c) Stop payload: `stop_hook_active`? | **Yes**, plus `last_assistant_message`, `background_tasks` (in-flight sub-agents) and `session_crons`. Claude Code caps consecutive stop-hook blocks (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`). | `stop-first.json`, `stop-final.json`. Block = exit 2 (stderr becomes the reason) or `{"decision":"block","reason":…}`. | 5.2 honours `stop_hook_active` and refuses the same tick-state hash only once; `background_tasks` non-empty counts as "in flight". |
| (d) SessionStart payload | `source: startup|resume|clear|compact|fork`; `agent_type`, `model`, `session_title`, `context_tokens` optional. No `permission_mode`. Output: plain stdout **or** `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"…"}}` is added to the model's context. | `sessionstart.json`; binary output schema `S0`. | 6.2 returns `additionalContext`; the matcher is the source (`startup|clear|compact|resume`). |
| (e) hooks.json schema: `onFailure`? `timeout`? | **Both exist.** `timeout` (seconds, positive), `onFailure: "continue" (default) | "block"` — "a failure of this hook: it could not start, timed out, exited with a code other than 0 or 2, or printed invalid JSON". Requires ≥ 2.1.295. Default command timeout 600 s. | Binary zod schema (`Ni`); docs. | 1.4 sets `timeout` and `onFailure: "block"` on every guard matcher **and** keeps the guard's own `signal.alarm` deadline (older plugins hosts ignore unknown keys; the alarm is the floor). |
| PreToolUse can warn on allow? | **Yes**: `hookSpecificOutput.additionalContext` on exit 0 is "added to Claude's context alongside the tool result" (ignored only for `defer`). | Binary schema `f0`; docs. | 5.4 warning does not need the next tick: the guard prints `additionalContext` at `caps.context_warn`. |
| Sub-agent transcripts | `<~/.claude/projects/<slug>/<session_id>/subagents/agent-<agent_id>.jsonl>`; records carry `isSidechain: true`, `agentId`, `attributionAgent` (the type). `SubagentStop` payload names it as `agent_transcript_path`. | `subagentstop.json`; live listing. | 0.1 `reef-cost.py` reads `<transcript dir>/<session>/subagents/*.jsonl`. |
| Transcript record shapes 0.1 relies on | One API turn = one `requestId` shared by every `assistant` record of that turn; `message.usage` is duplicated on each block. Context of a turn = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. Compaction = `{"type":"system","subtype":"compact_boundary","compact_metadata":{trigger, pre_tokens, post_tokens…}}` and a `user` record with `isCompactSummary: true`. | this session's transcript; the binary (`aF`, `isCompactSummary:!0`). | 0.1 counts turns by `requestId`; a compaction counts once (boundary preferred, summary as fallback). |
| Headless session id | A `claude -p` child inherits `CLAUDE_CODE_SESSION_ID` from a parent Claude Code session and writes its transcript under the child's project slug **with the parent's id**. | the scratch run's `session_id` equalled the parent's. | 0.3 `reef-eval` clears `CLAUDE_CODE_SESSION_ID`/`CLAUDE_CODE_REMOTE_SESSION_ID`/`CLAUDE_CODE_CHILD_SESSION` before spawning. |

What was **not** verified live: the AskUserQuestion result envelope (above); a `Stop` payload with `stop_hook_active: true` (requires a blocking stop hook in a live run; the field's presence and default are captured); PostCompact / compact-boundary records in a live transcript (shape from the binary's schema only — the 0.1 fixture mirrors it).
