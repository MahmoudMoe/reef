## Findings

### F1 — a vitest test name that mentions a flag is run as shell (breaks; Node/CLI projects) — FIX READY
`reef-converge`'s `looks_like_command` treated any ` --x`, `=` or `<>` in a backticked Proof cell as a command. A CLI's tests
name its flags, so row 2's proofs `` `prints empty for bare --slug` `` and `` `counts words when --slug is not exactly argv[0]` ``
ran as `sh` (`sh: prints: command not found`). 4 of 5 rows came back `missing`, a rollup was created, and it took one
proxy ruling, a plan amendment and a re-approval (s5, $1.02, ~5 min) to get past it. Row 1 passed only because its names
had no flag in them.
Fix (branch `claude/live-node-fixes`, red → green): a cell is a command when its head is a path, an assignment, `!` or a runner
word (`vitest`, `jest`, `tsc`, `echo`, `printf` added to the runners), or when it chains with `&&`, `||`, `|`, `;`, `$(`, `${`.
A flag, `=` or `<>` inside a sentence is the name's own text. Red: `AC-1: missing — prints empty for bare --slug (sh: prints:
command not found)`; green: tests/test_feature_spec.py 45 OK on python3 and /usr/bin/python3 3.9.

### F2 — a killed session's cost disappears from run.log (misleads the cost)
- A killed fresh session gets `"session": null, "cost_usd": null` (iteration 1, 368 s).
- A killed **resumed** session gets no run.log line at all: the runner falls back to a fresh session, and the only line is the
  fresh one's (the resume of 3becf4ba, 345 s).
The two killed sessions cost about as much as the rest of the run together (below). Cause: the cost comes only from the
stream's final `result` event; the session id is already in the first `system/init` event, and the resumed one is known
before the start. Proposed fix: the runner keeps the id from `init` (or the resume id), and a killed session writes its line
with `session` set and `cost_usd: null, "killed": true`, so `reef cost` can say "N killed sessions, cost unknown" instead of
showing a lower number as the total.

### F3 — the release under autopilot: the recommended answer is a dead end (repeats the Python run)
The release wait asks "Do I open the release PR develop → main now (you merge it)…?", recommends "Open the release PR now",
and prints `python3 scripts/reef-queue.py footnote '<that answer>' --row 2` as the command. But the guard refuses any agent's
release PR while `.reef/night/autopilot` exists (reef-guard.py:849, "Mahmoud never opens it"), and an owner footnote does not
change that. The Python run answered exactly this way and parked ("no progress: 3 identical ticks"). Proposed fix: under
autopilot the release wait names the owner's own command: either `gh pr create --base main --head develop` from the main
checkout (the owner's terminal is not guarded), or `python3 scripts/reef autopilot off`, then the footnote. It should not offer
a footnote the loop cannot act on.

### F4 — vitest runs the feature worktrees' tests from the main checkout (latent; Node only) — FIX PROPOSED
Feature worktrees live in `.reef/worktrees/` inside the repository. vitest's default exclude does not cover `.reef/`, so
`npm test` in the main checkout also runs every in-flight row's tests. Reproduced: one failing test planted in a worktree
turned the main checkout red (`.reef/worktrees/zz-probe/test/zz.test.ts`). It did not bite this run because every gate ran
inside a worktree. It bites the release's local `reef-ci-local.sh` and the owner's own `npm test` while a row is in flight.
pytest skips dot folders, which is why the Python run never saw it. day-zero lists "test discovery ignores `.reef/**`" as a
manual item.
Proposed fix: when vitest is the test runner, init renders `gates.full` = `npm test -- --exclude '**/.reef/**'` and the fast
gate `npx vitest run --changed --exclude '**/.reef/**'`. Checked on vitest 3.2.7: `--exclude` adds to the default excludes, the
planted test is skipped, and the real suite still runs.

### F5 — the first `reef autopilot` prints `reef-approval.py --owner ""`
It seeds `reef/proxy.md` but not `reef/owner.md`, and `day_digest` reads both, so the question is empty and the printed
command is unusable (against the "every wait prints the exact command" rule). `reef-run.py contract --day` seeds owner.md and
prints the right question. Proposed fix: autopilot seeds owner.md the way `contract --day` does (one shared helper), so its
first message carries the real question.

### F6 — NO REMOTE pushes only the integration branch (minor)
`gh repo create <name> --private --source . --remote origin --push` pushes the current branch (`develop`). `main` stays local,
and the release then needs it on origin (the Python run's footnote ⁷). Proposed fix: append `&& git push -u origin <release>`
when the release branch exists locally.

### F7 — doctor's `version:` line warns forever; the screen header says "Reef 0.7.3" (minor)
`.reef/version` is the layout version `0.7.3` (reef-init.py `VERSION`). doctor compares it with the plugin version
`0.7.4-dev.21` and names `reef update`, and the update re-renders 0.7.3. So it is a WARN on a fresh init and on reef-live too.
The 0.7.4 release set `VERSION` to 0.7.4, which hides it until the next -dev version. Proposed fix: compare the project's
layout version with the plugin's layout `VERSION`, and show the plugin version separately.
