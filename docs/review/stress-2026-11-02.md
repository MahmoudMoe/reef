## Coverage gaps (seams of the same class no suite attacked)

1. **reef-adversarial:237/250, the hunter's recorder.** It uses the same first-match `^VERDICT:` and the column-0 `^BLOCKER` reader as H3, and :317 counts FAIL rounds with the first match too. **Expect bugs.** These are certain from reading the code, and H3's helper closes them.
2. **reef-approval.py proxy paths** (`cmd_proxy` :216-241, `cmd_proxy_day` :287-298). The first `^WAIT` and the first `^DECIDE` decide independently, so a report carrying both is ambiguous. `feature_present` (:82) matches `^feature:[ \t]*<f>[ \t]*$`, which misses a quoted feature (M1). The Mahmoud decision binds the owner's contract. **Expect bugs.**
3. **reef-graph-run.py.** `mark_dispatched` (:236-255) rewrites `^status:.*$`, which eats the CRLF `\r`, reads `^feature:` with its quotes, and always writes the marker in MAIN, which is the origin of H2's shadowing. `verdict_of` (:653) reads `[A-Z]+` only, so `VERDICT: pass` gives '' and "ROW WAITS". Generate/collect after a workflow that died half-way is untested. **Expect bugs.**
4. **reef-row.py state machine.** `queue_status`/ready (:75-83) ignore rc, and a failure becomes `{}`/`set()`. A failed `gh pr list` (:184-191) silently falls back to git ancestry plus the review record, so a squash-merged PR can read as `merge` instead of `close`. This is H4's class in the command the SKILL calls "a row's one next step". **Expect bugs.**
5. **reef-run.py resume/restart with reef-guard check_stop.** `resume` (:675-690) trusts LAST_MODE, which M4 shows can be corrupted, and the hold. The Stop hook ticks `main_checkout(cwd)`, while the dispatch path writes the marker under `root`/`sub` per checkout. Nobody tested a runner restart after a crash mid-graph-run, or a Stop hook firing from a task worktree. **Likely bugs**, mostly H2 and H5 in new places. reef-converge looked defensive on rc (:288-329). **Low risk.**
