# Reef Task — the graph

**Input:** approved task files (`$ARGUMENTS`: a feature slug, task refs; empty — run `scripts/reef-graph.py status` and ask which).
**Output:** one merge per passed task into the feature branch (no push — that is `/reef-review`'s), each with its journal block in the task's `## Log`; the journal itself is written at the row's close, on the base.

You are the orchestrator: a MANAGER. You never write production code, never verify, never accept a report on faith. Read `.reef/config.json`.

## 0. Before the first dispatch, and each wave
- **Plan review** (before the first dispatch): `scripts/reef-plan-check.py --verify-stamp --feature <slug>` in the task's own worktree (the stamp is per worktree and feature). Non-zero = never reviewed or edited since: the machine review again (`reef-plan-review` on the critical path, the check alone on the fast path), show the human, continue.
- **The feature is current** (before each wave's first dispatch): `scripts/reef-merge-base` in the feature worktree — a stale `scripts/` in a task worktree computes a different plan digest than the records carry. Record files (journal, queue, archive, HANDOFF) keep both sides; a code conflict is exit 2 = USER ACTION REQUIRED, never resolved by you. Push the merge commit.

## 1. The ready set — computed, never remembered
**Evidence is the agent's, never yours**: a hand-back, a judge's report, a plan review is a file the agent wrote (the hand-back in its worktree; a report in the scratchpad, copied with `cp`); the guard refuses the main session writing one. An agent that returned text and no file is resumed (SendMessage: "write your report to <path>"), never transcribed.

**Read lean**: the tick, the task file in hand, and what the scripts PRINT. Never `git diff` code, never read `scripts/reef-*` source (the checkers are the oracle), never open a full report — `python3 scripts/reef-claims.py verdict <report>`, the full file only for a blocker's detail. Run `python3 scripts/reef-loop.py tick` (`--json` for the ids). `dispatch now:` lists every task whose `blocked-by` are done and whose `resources:` have a free slot, within `graph.parallel`; a broken graph (cycle, missing id) is exit 1 — STOP, a plan defect. `verify now:` = a hand-back newer than any report, its work uncommitted: start at step 3, never a second implementer. `dispatch (graph):` and `verify (graph):` are `/reef-graph`'s; this skill takes `dispatch (chat):`. **Dispatch every ready task now, in one message.** The guard refuses a task outside the ready set; a missing one is on you. End each turn with: `in flight: <ids or -> / waiting on: <what or -> / next: <the one command the owner runs>`.

## The path (v3)
`scripts/reef-attempt` prints it. **Fast** (a feature folder, every task light or full, no risk touch): `reef-graph.py worktree` answers the FEATURE worktree — the implementer works there one task at a time in id order, the commit gate on every commit, `verifier: none` (no judge, no hunter); no full suite here — it runs once per row, in `/reef-review`, on the head that merges; `reef-merge-close` commits each task in place. **Critical**: a worktree per task, the judges of step 3, the verifier's PASS report at the close.

## 2. Dispatch (per ready task)
1. `scripts/reef-graph.py worktree <task-file>` — creates or reuses `.reef/worktrees/<id>` on `task/<id>-<slug>` from the feature branch, running `worktree.setup`. The implementer works THERE; implementers never touch `tasks/`.
2. `scripts/reef-attempt <task-file>`. Exit 2 = blocked: print its USER ACTION REQUIRED, park the task, the graph continues. Otherwise use EXACTLY what it prints: the `author:` model as the Agent call's model, its effort in the prompt, and the prompt STARTS with its `REEF-TASK: <task-file>` line — as does every role dispatch for the task (implementer, verifier, hunter, mechanic): the guard resolves the tier's model per role from it and refuses any other model, a blocked or at-cap task, a stale stamp, a task outside the ready set; on allow it marks the task `in-progress`, advances `dispatches:`, and writes `.reef/inflight/<id>` (implementer) or `.reef/verifying/<id>` (judges) — `rm` each marker after its hand-back. `## Reviewer notes` are the plan review's advisories: the implementer does or declines each with one reason (not ACs; an unanswered one is the verifier's NIT).
3. Spawn the `implementer` with the task file, the worktree as its working directory, the resolved model and effort; prompt ≤ 120 words (the brief lives in the agent file). A mech task with a tiny diff (<~40 lines) MAY be done inline — say so in the Log. A design task with an empty `## Decision`: refuse.

## 3. Verify (in the task's worktree)
- `verify: gate-only` (mech): the fast gate there — headless, a runner job from the row's worktree (`python3 scripts/reef-run.py job gate-<id> -- sh -c 'cd <worktree> && sh scripts/reef-gate.sh fast --failures'`, then end the turn — /reef-loop § Long work; the base checkout has no task files); interactive, `scripts/reef-gate.sh fast --failures` (the exit code and the failing block, never the raw log). As the gate holds `gates.resources` itself, use `scripts/reef-graph.py lock heavy -- <cmd>` only around a heavy command outside the gate. Require a golden-output test for user-visible output. No judge subagent — do not add one.
- `verify: judge` (design): record `scripts/reef-snapshot.sh` (a content hash of HEAD + index + worktree), spawn the `verifier` fresh on that directory with the `verifier: model=` line's model, the `REEF-TASK:` line first and the `report: budget=` line verbatim. It is read-only by the guard and by the hash: re-run the snapshot after — ANY difference is a FAIL whatever the verdict. Require the `RUN:` header, a `RULE AC<n>` line per criterion ABOVE the verdicts, evidence per AC. On a retry the verifier attacks the last fix first.
- **The hunter** — `tier: design` or `critical`, and only when `reef-attempt` printed an `adversary:` line (its plan pass ran before code; with `guard-pass: feature` the one guard pass runs on the feature's diff in `/reef-review`): AT THE SAME TIME as the verifier, on the same snapshot, spawn the `loophole-hunter` with the `adversary:` model and the `hunter-report: budget=` line, snapshot-checked like the verifier. A PASS is recorded with `scripts/reef-adversarial <task-file> guard <report>` (the pre-commit refuses a design-tier close without it); a BLOCKER is a FAIL; a NEW-ROW is `scripts/reef-queue.py add-row --item … --source found --repo <main checkout>` (the queue lives on `branches.base` only); a NOTED line is `scripts/reef-queue.py note "<the line>" --row <row> --repo <main checkout>` (it refuses a security, privacy, money or data-loss finding: that one is a row).
- **Proof rows the judges cannot run** (they write: `[mechanic]`, a redirect, `rm`/`mv`/`touch`, `.env*`): the `mechanic` runs them verbatim in the worktree and records exit codes — never you.
- **A finding on a claimed AC = FAIL**: `scripts/reef-attempt <task-file> "<failure text naming AC-n>"`, then re-dispatch (step 2, same worktree, same slot); the next dispatch prints `rejudge: AC-n …` — pass it to the fix round's verifier, which judges only those. The implementer writes its hand-back to `.reef/ci-local/handback-<task>.md` (the path `reef-attempt` prints), checked by `scripts/reef-claims.py check --handback <file>`; a judge's report goes to `.reef/ci-local/report-<task>.md` **VERBATIM — its final message byte for byte, never a summary**, checked by `scripts/reef-claims.py report <file> --task <task-file>`. A fix round ends with a claims list (`<sentence> — true at <path>:<line>`, that round's diff only), checked by `scripts/reef-claims.py check <before>..<after> <claims-file>`. A rejected hand-back, report or list is re-dispatched ONCE ("shorten, evidence only") — no attempt consumed. Never launder findings into backlog tasks; only out-of-scope ones become new tasks, in the runlog's "Escaped defects" column.

## 4. Merge (on PASS only) — you are the feature branch's single writer
Write the task's journal block to a scratchpad file: the runlog row from the RUN: line, its `Orchestrator` cell from `python3 scripts/reef-cost.py growth <id> --repo <main checkout>` (an older journal without the column: `· growth N` in Result). Then ONE command in YOUR checkout, Bash timeout 10 minutes: `scripts/reef-merge-close <task-file> --subject "<Conventional Commits subject>" --journal <that file>`. It commits the task's worktree (refusing `.env*`, `.pem`, `.key`) with `Closes-task: <id>-<slug>` under the pre-commit gate — no bypass, ever; merges `--no-ff` into the feature (`worktree.setup` first when a lockfile changed); in that merge sets `status: done`, puts your block between `<!-- journal -->` lines in `## Log` (never edit `paths.runlog` on a feature branch: two features appending to it conflict at merge; the close copies the blocks), `git mv`s the file to `tasks/done/`, removes the worktree and branch. A conflict or gate refusal is exit 2 with nothing half-done — a code conflict is a person's decision. Task worktrees live under the MAIN checkout's `.reef/worktrees/`. Merge only after the agent's FINAL hand-back. Then step 1 again.

## 5. Stops
A blocked task parks itself; the graph continues. STOP when nothing is ready and nothing in flight: all done (hand to `/reef-review`), or only blocked tasks remain (USER ACTION REQUIRED, list them). Failure is a STOP, not an improvisation point.

## Trust nothing without evidence
Before advancing on a reported success: the named tests exist (`grep`), the claimed output reproduces (run it once, in the worktree), the diff stays in scope (`git diff --stat`). A hand-off without evidence is a FAIL, re-dispatched once with "evidence required" — no attempt consumed.

## Re-entry (session died / compaction)
1. `python3 scripts/reef-loop.py tick` — the only read at start: in flight, ready, parked, returned-but-unmerged.
2. Each `in-progress` task: `git -C .reef/worktrees/<id> status` — uncommitted work → step 3, never re-implement.
3. `status: blocked` → USER ACTION REQUIRED. Never reset attempts yourself — the human unblock is `attempts: 0`, `status: pending`, `last_failure_sig: ""`.

This file owns ONLY the per-feature graph loop; planning, review, the verification contract, the ready set and the cap live in reef-plan, reef-review, reef-verify, scripts/reef-graph.py and scripts/reef-attempt. No mid-loop human gates: the human gates are plan approval and the release.
