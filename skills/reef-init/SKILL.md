# Reef Init

Everything that is a FILE is rendered by `${CLAUDE_PLUGIN_ROOT}/scripts/reef-init.py` under one rule: absent → written; identical → skipped; **different → never overwritten** — the rendering goes to `.reef/proposed/<path>` with a printed diff, and only `--accept <path>` applies it, after the human read the diff. A second run with nothing changed writes nothing. The steps that are DECISIONS (hooks install, the first commit, CI) stay here.

0. Prerequisite: `command -v python3` — the gates and scripts need it. Missing → STOP and say so.
1. Verify this is a git repo (`git rev-parse`); if not, ask before `git init`. Ask ONE batched question set (AskUserQuestion), recommended first: the integration branch and the release branch (default `develop` → `main`; same branch = the human merges everything, `merge.by: human`, CI on every PR); the project name if `package.json`/`pyproject.toml` do not say it. Nothing else is asked — everything else has a default the human can change in `.reef/config.json`.
2. PREFLIGHT the hook surface — never clobber someone else's hooks: `git config --get core.hooksPath` non-empty (and not `.githooks`), or `.git/hooks/` contains non-`.sample` hooks (husky, lfs, pre-commit.com)? → STOP, show what exists, and ask whether to chain (call the existing hook from `.githooks/pre-commit`) or abort.
3. Run `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/reef-init.py --root . --base <base> --release <release> [--name <name>]`. It detects the stack (package.json, pyproject/uv.lock, Cargo.toml, go.mod) and writes, adapted: `.reef/config.json` (merged — a key the project already has is never changed; `gates.full` from the stack, empty when none was detected: the gate FAILS LOUDLY until set, never a no-op), `AGENTS.md` + a one-line `CLAUDE.md` pointer (only when absent), `.specify/constitution.md`, `docs/queue.md`, `docs/adr/README.md`, `docs/journal.md` (= `paths.runlog`), `HANDOFF.md`, `docs/day-zero.md`, `docs/glossary.md`, `.github/workflows/ci.yml` (PRs into the release branch only) and `.github/dependabot.yml` (targets the integration branch), `.githooks/pre-commit` + `pre-merge-commit`, every `scripts/reef-*` (gate, attempt, snapshot, plan-check, graph, adversarial, claims, ci-local, tier, queue), `tasks/` + `tasks/done/`, `.gitignore` lines (`.reef/worktrees/`, `.reef/proposed/`, `.reef/ci-local/`, the plan stamp `tasks/.plan-review.json` — per-worktree state, never committed — and `.env`), a Makefile `setup:` target (appended, never rewritten). Read its summary. For each PROPOSED file: show the human the diff, ask in the same batched question whether to accept it, and run `--accept <path>` only for the ones they chose. Never hand-edit a generated file to make it fit — change the project's own file or accept the rendering.
4. Install the hooks: `chmod +x .githooks/*`, then `git config core.hooksPath .githooks` (the guard allow-lists exactly this value). NO pre-push hook by design: at push time the worktree has no relationship to the refs being pushed; CI is the push wall. hooksPath is local config and does not survive a clone; `make setup` is documented step 0 (not per worktree — `reef-graph worktree` runs `worktree.setup`).
5. Stage and commit everything this init created (one commit, `chore: reef init`) — the pre-commit gate must never trip over its own untracked config on the first real commit. Specific paths, never `git add -A` over a dirty tree.
6. Say what remains: `docs/day-zero.md` lists the gates still open (test command if none was detected, `gates.fast`, the light-tier allowlist, "Owner decision points", the first batch's rows, review-toolkit agents installed). Print the one next command: `/reef-loop` when the queue has a row, `/reef-plan <spec>` otherwise.

## Existing projects (adoption, upgrade)
Run the same command. Nothing you wrote is overwritten: your `AGENTS.md`, `CLAUDE.md`, CI workflow, Makefile and config keep their content and the differing renderings wait in `.reef/proposed/` with their diffs — adopt one, merge one by hand, or ignore one. Config: missing keys are added with their defaults (`graph`, `resources`, `worktree`, `tiers`, `writing`, `roles.*`, `branches`), existing values are kept. After a plugin upgrade, re-run it: the scripts under `scripts/` that changed are proposed, not replaced — accept them (they are Reef's, not yours). 0.3 stamps are read as missing: run `/reef-plan-review` once.
