# Reef Graph — the task graph as a workflow

Chat mode (`/reef-task`) costs the orchestrator one 90k-context turn per agent result. Graph mode moves the per-task chain into a workflow script that `scripts/reef-graph-run.py` writes from the tick; the orchestrator makes three calls per batch of tasks and reads one summary. Every record and check stays: reef-attempt and the plan gate run at generation, the gate and the snapshot run as a `reef:mechanic` agent inside the pipeline, the judges are the same agents with the same budgets and write their report FILES, the report checks and the guard-pass record run at settle, and the merge stays with you, the single writer.

## 0. The gate — once per machine, fail closed
`python3 scripts/reef-graph-run.py probe` writes `.reef/graph/probe.js`. Call the **Workflow** tool with `scriptPath` set to it. Its one agent (`reef:mechanic`) tries `printf '{}' > .reef/approvals/graph-probe.json`. Save the tool's return value verbatim as JSON to `.reef/graph/probe-results.json` (not an evidence path), then `python3 scripts/reef-graph-run.py probe-check .reef/graph/probe-results.json`. `GATE OK` means PreToolUse hooks reach workflow agents here and `.reef/graph/gate.json` records it; `GATE FAILED` means a workflow is a way around the guard on this machine — graph mode stays OFF (`generate` refuses) and `/reef-task` keeps every guarantee. Say which to the owner in one line.

## 1. Generate
`python3 scripts/reef-graph-run.py generate [--tasks 101,102]` — for every task in the tick's `dispatch now`: the worktree (`reef-graph.py worktree`), `reef-attempt` (caps, models, budgets; exit 2 = parked, listed as `skipped`), the in-progress status, the dispatch count and the `.reef/inflight/<id>` marker (what the guard writes on a chat dispatch), then `.reef/graph/run-<hash>.js`. Read only its `graph:`, `skipped` and `next:` lines.

## 2. Run
Call the **Workflow** tool with `scriptPath` = the printed script. Do nothing else while it runs; the Stop hook's tick shows the tasks in flight. The workflow returns `{tasks: [...], skipped: n}`: per task the gate exit, the hand-back check line, the snapshot before and after the judges, each judge's verdict and report path. Settle the output file its completion notice names, as it is — never type the result out (auto mode blocks a hand-typed results file as a possible checks bypass).

## 3. Settle
`python3 scripts/reef-graph-run.py settle <that output file>` — per task: the gate must be 0, the hand-back check `ok`, the snapshot unchanged across the judges, every verdict PASS; the verifier's report is copied (`cp`, the agent's words) into the worktree's `.reef/ci-local/` and checked with `reef-claims.py report`, the hunter's PASS recorded with `reef-adversarial … guard`; the in-flight marker is removed; the hunter's `NEW-ROW` and `NOTED` lines are printed — file each (`reef-queue.py add-row --source found` / `reef-queue.py note`), on `branches.base`. `READY TO MERGE <id>` → `/reef-task` step 4 for that task (commit in the worktree, `merge --no-ff` into the feature branch, `status: done`, the journal row with `reef-cost.py growth <id>`). `FAIL <id>: <why>` → the attempt is already counted (`reef-attempt <task> "<why>"`); the next `generate` re-dispatches it with the failure text, under the same caps.

## The row (v3 phase 5b) — three calls per ROW, not per task
When `reef-row.py state` says `build`, `evidence` or `review`: `python3 scripts/reef-graph-run.py row <row>` writes `.reef/graph/row-<slug>-<hash>.js` — the row's open tasks in id order, each implemented, gated, judged on the critical path and **closed in place by the mechanic (`reef-merge-close`) before the next starts**; then the full gate and `reef-converge` once, `reef-merge-base` + push + PR, the critical path's guard pass and security, and the ONE reviewer (`reef:acceptance`). Run it with the Workflow tool, then `settle <its output file>` as above: every close is checked on disk, the evidence re-read, the reports copied and recorded (`reef-record`), and it prints `ROW <id> READY TO MERGE … gh pr merge <n> --squash --delete-branch` — **you run that one command bare** (the guard checks the record, the base tip and the evidence there; a script's merge would pass no hook) — or `ROW <id> WAITS <state>: <why>` (a failed task's attempt is counted; the next `row` re-dispatches with the failure). The driver refuses the owner's steps (plan, approval), the scripts' (merge, close) and a row with a task in flight.

## Rules
- The results files are summaries, not evidence: the evidence is the hand-back in the worktree and the report files the judges wrote; the guard still refuses you writing those.
- A task the results omit (the agent died or was skipped) stays in flight: `generate` skips it, and the tick frees it after `loop.inflight_stale_minutes` (90) — a workflow killed mid-run leaves its partial work in the worktree for the next implementer, judged like any other. `settle` clears every marker it sees in the results.
- Measured (`docs/perf/2026-10-18.md` §C): the first graph-mode task cost the orchestrator 6 turns at ≤ 46k where chat mode paid ≈ 25 at 90–150k; `graph.mode: auto` (read from the main checkout) now makes the tick name the mode per task — `dispatch (graph)` and `verify (graph)` → this skill, `dispatch (chat)` → `/reef-task` (no gate, or `graph.mode: chat`). A fix round runs here: `generate` hands the implementer the last FAIL line and the gate log, the verifier the `rejudge:` line and the round; after a rejected report, or for a hand-back, it builds a judge-only pipeline (no implementer, no dispatch counted, a full judge after a rejected report). `reef-cost` attributes a Workflow call's tasks (from the script's `REEF-TASK:` lines) to their features and tasks as role `workflow`.
