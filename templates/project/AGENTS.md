# AGENTS.md

Instruction layer for any coding agent working in this repository ({{name}}). Format: the [AGENTS.md open standard](https://agents.md).
Generated by `/reef-init`; every number below lives in `.reef/config.json` — this file points, it does not restate.

## Read first
`HANDOFF.md` — where the project stands, rewritten whole at the end of every session. It is a **map, not an authority**: where it and the repository disagree, the repository is right (`git log`, `scripts/reef-ci-local.sh`, `docs/journal.md`), and saying so is part of the work. Then `.specify/constitution.md` (the rules that never bend) and `docs/queue.md` (the work).

## How work flows (the loop is a graph)
1. **A queue row** (`docs/queue.md`, current batch, a `planned` row before a `found` one) → `/reef-plan`: grill, slice into task files with real `blocked-by` edges, declared `resources:` (ports, the database, the browser, `heavy`) and a `tier:`; one batched question set for the owner; `/reef-plan-review`.
2. **`/reef-task`** runs the task set as a graph: every ready task is dispatched at once, each implementer in its own worktree (`.reef/worktrees/<id>`, its own installed dependencies and generated code — never the shared copy); implement → verify → merge into the feature branch, under the retry cap in `.reef/config.json` (`caps.attempts`). The guard refuses a dispatch outside the ready set, a blocked or at-cap task, a stale plan, a wrong model.
3. **`/reef-review`**: push, PR into `{{base}}`, acceptance review, diff review (`code-excellence` when installed), the local gate (`ci.feature_gate`), one rollup under the same cap; the loop merges when `merge.by` is `loop`.
4. **Close in the same breath as the merge** (single writer, on `{{base}}`): row archived, draft ADR numbered, journal entry, branch and worktree deleted.
5. **Release**: a PR from `{{base}}` into `{{release}}` is the owner's merge; CI runs there and only there; a fresh orchestrator starts after it (`/clear`, then `HANDOFF.md`).

The loop does not wait for approval inside an item. It stops only for: a decision that is the owner's (below), a missing credential or quota, a spec found wrong (amend it, push, resume), or the cap.

## The rules that cost the most when broken
- **A GREEN stage is over.** After GREEN: one claims-only commit at most (`scripts/reef-claims.py claims-only`); a code should-fix is the reviewer's BLOCKER or a new row. Never a fourth round.
- **One place per fact.** A number, list or decision lives in one file; everything else points at it. A restated fact is the sentence the next review blocks on.
- **Never `git stash`** (the guard denies it): one stack serves every worktree. Commit to the task branch or open another worktree.
- **Never pipe a gate** into `tail`/`grep` (the guard denies it): read the exit code. A skipped gate is not a passed gate: `reef-ci-local.sh` exits 2 for a skip, and 2 is not success.
- **Never regenerate a shared generated file** (an ORM client, a build artefact) from a worktree, and never restore one under a running server. Each worktree runs `worktree.setup` for its own copy.
- **Merge only after the agent's final hand-back**, never on seeing its report file.
- **The batch is frozen.** Work found mid-batch waits for the next batch unless it is in the constitution's fix-now class (Article VII) — journaled with its ground.
- **A guard refuses by shape with a small closed exception list.** A fix that turns "refuse unless excepted" into "pass unless listed" is the next round's finding.
- **"Cannot verify here" needs the probe pasted** — the command and its exit code. Check for the local database before claiming there is none.
- **Spec before code** (the task file is pushed first); **author ≠ verifier**; the verifier writes its pass/fail rule per criterion before reading the diff; every re-review attacks the last round's fix first.

## Parallel by default
After every hand-back, before replying, launch every task the graph reports ready (`scripts/reef-graph.py ready`) and every queue row that is ready — up to `graph.parallel`, heavy commands through `scripts/reef-graph.py lock heavy -- <cmd>`. Do not ask. End each reply with one line: `in flight: … / waiting on: …`. The collision table is `resources` in `.reef/config.json` plus each task's `resources:`; a resource nobody declared collides once before it is added — add it then.

## Tiers (effort matched to risk)
`tier:` on every task; `scripts/reef-tier.py` recomputes it from the diff and can only make it heavier (`tiers` in `.reef/config.json`: the light allowlist, the line ceiling, migration paths). `light` ⇔ `mech` (gate + golden test); `full` is the default; `design` (a mechanism that failed twice, privacy, money, a guard) runs the `loophole-hunter` on the plan before code and on the finished guard after.

## Writing
Every sentence about the code is a claim someone must check. Point, don't narrate. Caps live in `.reef/config.json` `writing` (task file words per tier, hand-back words, prompt words). A fix round ends with a claims list (`<sentence> — true at <path>:<line>`, that round's diff only — `scripts/reef-claims.py check`). Reports keep one shape: head · verdict · gates (exit codes) · what changed (one line each) · claims · stopped on. A reviewer may flag text to delete.

## The model for each job
`roles.*` in `.reef/config.json`, read at dispatch and enforced by the guard: planning on `roles.planner` / `roles.plan_reviewer`; code, verification, review, security and the adversarial passes on `roles.author` / `roles.verifier` / `roles.reviewer` / `roles.security` / `roles.adversary`; mechanical work (rebase, gates, records, archive moves — anything a machine checks) on `roles.mechanic`, which writes no prose claims. Prompts stay short: the stable brief is the agent definition.

## Owner decision points
Only the owner decides: personal data leaving the system, commercial claims, the look of his own product, money, a rule change. Everything else the loop decides and records. Decisions are **batched** at fixed points — end of a merge wave, before a release, or when one blocks the critical path — in one question set, each question with 2–4 options, the recommended one first, one line of trade-off each. An unanswered question takes its default, except for personal data, a commercial claim and a visible change to his product. Design work gets a full previewable page of every screen before any build. Each answer is recorded verbatim as a queue footnote.

## Boundaries — do not touch without being asked
- `.env` (read `.env.example` for the shape); secrets never enter the repository (CI scans the full history)
- migration directories once they exist — a schema change is not complete without its migration beside it
- the owner's deployments and databases: nothing in this repository connects to them
